# PMBOK GitHub Risk

GitHub Issues + Actions でリスク管理を構築する。

## このスキルを使用する場面

- リスク登録簿を GitHub Issues で管理する体制を構築する
- 発生確率・影響度のカスタムフィールドを設計する
- リスク値（発生確率 × 影響度）に応じた自動アラートを設定する
- リスクレビュー会議用のサマリレポートを生成する

## 必須入力

- 対象リポジトリ（Owner/Repo）
- GitHub Project 番号
- リスクオーナー（デフォルト Assignee）のルール（任意）

## ワークフロー

1. リスク管理用カスタムフィールドの確認（`risk_probability`, `risk_impact`, `priority_score`）
2. リスク登録用 Issue テンプレートを生成（`assets/risk-register-template.yml` を再利用）
3. リスクスコア自動算出 Actions を生成
4. 高リスク Issue への自動メンション Actions を生成
5. リスクサマリレポート生成 Actions を生成

## リスク評価マトリクス

|  | 影響度: 低(1) | 影響度: 中(2) | 影響度: 高(3) |
|--|-------------|-------------|-------------|
| 確率: 高(3) | 3 (中) | 6 (高) | 9 (最高) |
| 確率: 中(2) | 2 (低) | 4 (中) | 6 (高) |
| 確率: 低(1) | 1 (最低) | 2 (低) | 3 (中) |

## アラートルール

| リスク値 | アクション |
|---------|----------|
| 7-9 (最高) | Issue にリスクオーナー + PM を自動メンション、`risk:critical` ラベル付与 |
| 4-6 (高) | Issue にリスクオーナーを自動メンション、`risk:high` ラベル付与 |
| 2-3 (中) | `risk:medium` ラベル付与のみ |
| 1 (低) | `risk:low` ラベル付与のみ |

## 成果物

- `risk-report.md`: リスク管理設定の概要
- `.github/workflows/risk-scoring.yml`: リスクスコア算出・アラートワークフロー
- `.github/ISSUE_TEMPLATE/risk-register.yml`: リスク登録テンプレート
- リスク登録テンプレートを生成する際に `assets/risk-register-template.yml` を再利用する

## Quality Gates

- [ ] リスク値算出が確率×影響度の数値マッピングと一致している
- [ ] 高リスク Issue へのメンション対象が正しく設定されている
- [ ] リスク値 0 やフィールド未設定の場合のフォールバック処理がある
- [ ] リスクラベルが他の知識エリアのラベルと重複していない

## Gotchas

- `Single Select` 型の発生確率・影響度は文字列として格納される。数値スコアへの変換マッピングを Actions 内で定義する必要がある
- リスク値の自動算出は `projects_v2_item.edited` イベントでトリガーするが、このイベントはベータ機能の場合がある。代替として `schedule` トリガーでの定期バッチも用意する
- `@mention` をコメントに含める場合、Actions の `GITHUB_TOKEN` では外部ユーザーへの通知が飛ばないことがある。Organization メンバーなら問題ない
- リスク登録簿の Issue が大量（50件超）になると GraphQL クエリのパフォーマンスが低下する。`type:risk` ラベルでフィルタリングを最適化する

## 検証ループ

1. リスクスコア算出ワークフローとテンプレートを生成
2. チェック:
   - スコア計算マッピングが評価マトリクスと一致しているか
   - フィールド未設定時のフォールバックがあるか
   - Actions YAML の構文が正しいか
3. 不合格の場合:
   - マッピングテーブルを修正
   - フォールバック処理を追加
   - YAML 構文エラーを修正
4. 全ゲート合格後のみ成果物を出力
