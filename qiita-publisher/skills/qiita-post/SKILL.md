# Qiita Post

ブラウザ操作で Qiita に記事を入力・保存・投稿する。

## このスキルを使用する場面

- 記事コンテンツを Qiita エディタに入力する
- 下書きを保存する
- 保存済み下書きの投稿設定（キャンペーン登録等）を行う
- 記事を公開する

## 前提条件

- ブラウザ操作ツール（Playwright MCP 等）が利用可能
- Qiita にログイン済みのブラウザセッション
- 投稿するコンテンツ（タイトル・タグ・本文）が準備済み

## ワークフロー

### Phase 1: エディタ入力

1. `https://qiita.com/drafts/new` を開く
2. タイトル入力欄にタイトルを入力
3. タグ入力欄にタグをスペース区切りで入力
4. 本文エディタに CodeMirror API で全文入力（**references/qiita-editor-api.md を参照**）
5. 「下書きを保存する」ボタンを押下
6. 保存成功を確認（URL 遷移 or トースト表示）

### Phase 2: レビュー・投稿

1. 保存済み下書きの編集ページを開く
2. プレビューでコンテンツ表示を確認
3. ⏸️ ユーザーに内容確認を求める
4. 「公開設定へ」ボタンを押下
5. 投稿設定モーダルで以下を実施:
   - 該当するキャンペーンがあれば「登録する」を押下
   - 「記事を投稿する」ボタンを押下
6. URL 遷移を確認（`/drafts/xxx/edit` → `/items/xxx`）
7. 公開ページでタイトル・タグ・冒頭の表示を確認

## CodeMirror エディタ操作

**本文入力時は必ず `references/qiita-editor-api.md` を参照してから操作すること。**

## 成果物

- Qiita 上の公開記事（URL）
- 投稿確認結果のチャット報告

## Quality Gates

- [ ] タイトルがエディタに正しく入力されている
- [ ] タグが全て緑色 span で有効として認識されている
- [ ] 本文が全文正しく入力されている（冒頭・末尾を確認）
- [ ] 下書き保存が成功している
- [ ] 投稿後の URL が `/items/` に遷移している
- [ ] 公開ページでタイトル・タグ・本文冒頭が正常表示されている

## Gotchas

- CodeMirror エディタに `type_in_page` で直接入力すると、既存テキストとの結合で文字化けや部分入力が発生する。必ず `cmTile.view.dispatch` API で全文差し替えすること
- タグ入力後、各タグが緑色の span（`var(--color-greenContainerVariant)` 背景）で表示されれば有効。表示されない場合はタグ名のスペルを確認
- 「公開設定へ」ボタンを押すとモーダルが開く。このモーダル内にキャンペーン登録ボタンと「記事を投稿する」ボタンがある
- 下書き保存せずにページ遷移すると内容が消失する。操作の区切りごとに下書き保存すること
- 既存の下書きを編集する場合の URL は `https://qiita.com/drafts/<id>/edit`

## 検証ループ

1. ブラウザ操作で入力・保存を実行
2. チェック:
   - 各入力欄の表示内容が期待通りか（スナップショット確認）
   - 下書き保存後の URL・トースト表示
   - 投稿後の URL 遷移（`/items/` パス）
3. 不合格の場合:
   - 入力が不完全 → 再入力（CodeMirror API で全文差し替え）
   - 保存失敗 → ページリロードして再試行
   - 投稿失敗 → エラーメッセージを確認し対処
4. 公開ページの表示確認後、ユーザーに報告
