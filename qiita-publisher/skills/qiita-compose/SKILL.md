# Qiita Compose

Qiita 投稿用の記事コンテンツを企画・構成・生成する。

## このスキルを使用する場面

- 技術記事のネタ出し・テーマ決定
- 記事タイトルとタグの選定
- Markdown 本文の構成設計と執筆
- 既存原稿のブラッシュアップ・推敲
- AI 使用注釈や文脈情報の追加

## 必須入力

- 記事のテーマまたは技術トピック
- 想定読者層（初心者向け / 中級者向け / 上級者向け）

## ワークフロー

1. **テーマ分析**: トピックの技術的ポイントと読者への価値を整理
2. **構成設計**: 見出し構成（H2/H3）を設計し、論理的な流れを組み立てる
3. **タイトル案**: SEO とクリック率を意識した候補を 2〜3 案提示
4. **タグ選定**: Qiita で有効なタグを 3〜5 個選定（人気タグ優先）
5. **本文生成**: Markdown 形式で本文を生成
6. **セルフレビュー**: 品質基準に照らしてチェック
7. **ファイル保存**: `drafts/<slug>.md` にローカル保存

## 記事構成ガイドライン

### 推奨構成

```
# タイトル
> AI 使用注釈（必要な場合）

## はじめに（動機・背景）
## 前提知識 / 環境（必要な場合）
## 本題（複数セクションに分割）
## 学び・気づき
## まとめ
## 参考リンク
```

### タイトルの原則

- 「何をしたか」が伝わる具体的な表現
- 技術キーワードを含める
- 30〜60 文字程度

### タグ選定の原則

- 記事の主要技術を必ず含める（言語名、フレームワーク名）
- トレンドタグや Qiita 公式イベントに関連するタグを優先
- 3〜5 個が最適（最大 5 個）

## 成果物

- `drafts/<slug>.md`: 記事本文（Markdown）
- チャット出力: タイトル案、タグ案、構成の要約

## Quality Gates

- [ ] タイトルが具体的で技術キーワードを含む
- [ ] タグが 3〜5 個で記事内容に適合
- [ ] 見出し構成が論理的で H2/H3 が適切に使用されている
- [ ] コードブロックに言語指定がある
- [ ] 冒頭 3 行で読者の関心を引ける
- [ ] 誤字脱字・文法エラーがない

## Gotchas

- Qiita のタグは大文字小文字を区別する。公式表記に合わせること（例: `TypeScript` ではなく `TypeScript`、`github` ではなく `GitHub`）
- タグは最大 5 個まで。6 個以上指定するとエラーになる
- 記事が長すぎる（1 万字超）と読了率が下がる。必要に応じてシリーズ分割を検討する
- 画像は Qiita のドラッグ & ドロップアップロードを使う。外部画像 URL はリンク切れリスクがある

## 検証ループ

1. 生成した記事コンテンツを確認
2. チェック:
   - Quality Gates を全項目確認
   - 技術的な正確性を確認（コード例が動作するか）
   - 読者視点で流れが自然か
3. 不合格の場合:
   - 問題箇所を特定し修正
   - 再チェック
4. 全ゲート合格後、ユーザーに承認を求める
