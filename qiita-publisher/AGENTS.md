# Qiita Publisher Orchestrator v0.1.0

Qiita 記事の企画から投稿までを管理する。最も適切なサブスキルにルーティングし、全ての成果物をファイルに保存する。

## 基本ルール

- 記事コンテンツはユーザーの入力と同じ言語で記述する
- 全ての成果物をファイルに保存する。チャットにのみ結果を残さない
- ブラウザ操作前に Qiita ログイン済みであることを確認する
- 投稿前に必ずセルフレビューを実施する

## ルーティングルール

### WHEN/DO ディスパッチ

WHEN: 記事のネタ出し、構成相談、タイトル案、タグ選定、本文の執筆・推敲
DO: → `qiita-compose`

WHEN: Qiita への入力、下書き保存、キャンペーン登録、記事の公開・投稿
DO: → `qiita-post`

WHEN: 記事の企画から投稿まで一気通貫で行いたい
DO: → フルワークフロー（Phase 0 → Phase 1 → Phase 2）

### タスク分類

1. コンテンツの生成・修正が必要？
   - YES → `qiita-compose`
   - NO → 次へ
2. ブラウザ操作で Qiita に入力・投稿が必要？
   - YES → `qiita-post`
   - NO → 直接回答

### フルワークフロー

Phase 0 → `qiita-compose`: 記事コンテンツの企画・生成 ⏸️ ユーザー承認
Phase 1 → `qiita-post`: ブラウザ操作で Qiita に入力・下書き保存
Phase 2 → `qiita-post`: セルフレビュー → 投稿設定 → 公開 ⏸️ ユーザー承認

### 緊急度トリアージ

| 緊急度 | キーワード | ワークフロー |
|--------|-----------|------------|
| 通常 | （デフォルト） | フルワークフロー |
| 急ぎ | 「急ぎ」「すぐ投稿」 | レビュー簡略化 |
| 下書きのみ | 「下書き」「ドラフト」 | Phase 0-1 で停止 |

## 検証ループ

計画 → 実行 → 検証 → 報告 → 記録

## Quality Gates

- [ ] タイトルが内容を正確に反映している
- [ ] タグが 1〜5 個、記事内容に適合している
- [ ] 本文が Markdown として正しく構造化されている
- [ ] コードブロックの言語指定が正しい
- [ ] リンクが有効である
- [ ] 投稿後の公開ページで正常表示を確認している

## 禁止事項

- ユーザー承認なしに記事を公開しない
- 他者の記事やコードを無断で転載しない
- Qiita の利用規約に反するコンテンツを生成しない
- ログイン操作（パスワード入力）を自動化しない
- ブラウザのセッション Cookie やトークンをログ・ファイルに記録しない
- 社外秘情報・個人情報を記事コンテンツに含めない（ユーザーが明示的に許可した場合を除く）

## Gotchas

- Qiita エディタは CodeMirror ベース。通常の `type` では部分入力になるため、`cmTile.view.dispatch` API で全文差し替えが必要
- タグ入力はスペース区切り。タグが有効なら緑色 span でハイライトされる
- 「公開設定へ」ボタンを押すとモーダルが開き、キャンペーン登録と投稿ボタンが表示される
- 下書き保存後にページ遷移すると未保存の変更が失われる
